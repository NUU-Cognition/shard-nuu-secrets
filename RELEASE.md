# Release notes

The notes of each version of the shard `nsec` (`@nuucognition/nuu-secrets`). The notes of the versions before 0.6.0 are in the Git history of this repository.

## 0.7.0

For the CLI of npm `@nuucognition/secrets-cli@0.2.0-beta.0`, built from the draft commit `9b7ad5c` of `NUU-Cognition/secrets` (not on canon, which is `633496d`). Install it with the exact version: `npm install -g @nuucognition/secrets-cli@0.2.0-beta.0` (the npm tags `beta` and `latest` still give `0.1.0-beta.1`). It adds the change log, `secrets mv`, the ref check, the collections, and the expiry dates (Notepad 005) to the CLI of canon `633496d`. Canon `633496d` and npm `0.1.0-beta.1` do not have these parts.

- **Rule 13: moved refs, collections, and expiry dates.** Agents can run `secrets log`, `secrets refs`, `secrets refs fix --dry-run`, `secrets collection list`, and `secrets expiry list`. Agents run `secrets mv`, `collection create|edit|rename|rm`, `expiry set|clear`, and `refs fix` only with the approval of the operator (Rule 5). The approval names the exact command: a general task such as "fix the refs" is not an approval. With no terminal, `refs fix` needs `--yes`: the agent adds it only after the operator approved the plan of `--dry-run`, and runs `--dry-run` again first. A missing ref with a `moved` hint leads to `secrets refs fix --dry-run` and a question to the operator; a `removed` ref is a question to the operator. An expiry warning (`due` or `expired`) goes to the operator; the agent never sets or clears a date. In a headless session, a moved or removed ref is a blocker, and an expiry warning goes into the result. The rule is in the rules, the init (item 13), and the headless init (item 10).
- **Rules 2, 4, 5, 6, 7, 10, and 11:** `secret <cmd>` writes no `.env` file (a file with values comes only from a redirect of `secrets export`), and the Convex names of `.env.local` (`CONVEX_DEPLOYMENT`, `NEXT_PUBLIC_CONVEX_URL`) stay out of `secrets.toml`; no hand edit of `collections.toml`, `metadata.toml`, or `changes.jsonl`; the new operator and agent commands; a moved ref is not a missing value; the page shows the collections and the change log.
- **Diagnose:** the new step 7 (moved and removed refs: `secrets refs`, `refs fix --dry-run`, the request for approval, `--yes` only after the approval), the `doctor` lines of moved refs and expiry dates, and the new lines of `store sync`. The steps 7 to 10 of 0.6.0 are now 8 to 11.
- **Request a value, run an app, and plan a push:** a moved or removed ref is not a missing value; the optional warning; the expiry warnings; `plan` stops on a moved `optional` ref. The page way of `request_value` names the store choice.
- **Set up a project:** use an existing collection for a new secret name (`secrets collection list`), make no collection record, and give the Convex names no entry.
- **The model:** the new store files (`collections.toml`, `metadata.toml`, `changes.jsonl`), and the sections Collections, Expiry dates, and The change log and moved refs (the trace and the states of `secrets refs`).
- **The CLI reference:** the install of `0.2.0-beta.0`, `secrets log`, `secrets refs`, `refs fix --dry-run`, `collection list`, `expiry list`, the operator commands `mv`, `collection create|edit|rename|rm`, `expiry set|clear`, `set --expires`, and `refs fix`, the hints and warnings of `secret <cmd>`, `export`, `plan`, and `doctor`, the new `store sync` lines, the new messages, and the known limits 28 to 30.
- **The setup guide:** the section "Collections, expiry dates, and the change log" (operator commands), and the page of `0.2.0-beta.0`: the login link unlocks with the one identity, the store choice, and the side bar of the store (projects, collections, Activity, Health).

## 0.6.0

For the CLI of Mission 002 (canon `633496d`): the CLI of canon `471e270` with the identities, the project index, and the local web page `secrets ui`. The npm version `0.1.0-beta.1` does not have these parts.

- **Rule 11: `secrets ui` is for the operator.** Agents never run `secrets ui` (also when the operator asks, and with no way around the terminal check), never open its URL, login link, page, or API, and never read values from it. A login link is a credential. The rule is in the rules, the init, and the headless init.
- **Rule 12: identities.** The agent uses the identity that the CLI selects. It does not add `--identity` or set `SECRETS_IDENTITY` or `SOPS_AGE_KEY_FILE` unless the operator names the identity. `identity add|use|rm`, `project identity <name>`, `project identity --clear`, and `project forget` are operator commands. `identity list`, `project list`, and `project identity` (show) are agent commands. On `LINKED_MAPPING`, `MAPPING_CHANGED`, `OUTSIDE_PROJECT`, `DUPLICATE_PROJECT`, `UNKNOWN_IDENTITY`, `PROJECT_INDEX`, the parent-identity warning, or the link warning, the agent stops and gives the operator the exact message and the remedy of the CLI. In a headless session, these are blockers.
- **The model:** the selection order of the key (`--identity`, `SECRETS_IDENTITY`, `SOPS_AGE_KEY_FILE`, the project identity, the default, the default key file), where the project identity applies, and the project index.
- **Request a value:** the operator sets a value with `secrets set` or in the page of `secrets ui`; then the agent continues with `secret <cmd>`. The key request covers the key file of an identity.
- **The setup guide:** the sections Identities (make the identity with the least access the default), The project index (`project list|forget`), and The UI: `secrets ui` (the start, the login link, the identity choice, the lock, the hidden values, the writes, Quit).
- **The CLI reference:** `--identity` on each command that decrypts or reads the key, `identity list`, `project list`, `project identity`, the operator commands `identity add|use|rm`, `project identity <name>`, `project forget`, and `secrets ui`, the `doctor` lines of the key selection and the project index, the identity messages, and the new known limits (items 23 to 27).
- **`secrets project add <path>`** (an agent command): it finds each `secrets.toml` under a folder (or takes one `secrets.toml`) and adds its project to the project index. It writes only `projects.toml` and reads no store and no value. In Rule 6, the CLI reference (the search, the limits, the line words `added`, `updated`, `known`, `skipped <reason>`, `--dry-run`, `--json`, and the codes `NO_FOLDER`, `LINKED_FOLDER`, `BAD_FOLDER`), the setup guide (the project index, and "Add projects from a folder" of the page when the side bar has no projects), the model, and `diagnose` (step 6: a missing project, first with `--dry-run`).
- **The page writes in part:** `Only a part of the change was saved.` (`PARTIAL_WRITE`) with "Undo the saved part" for 60 seconds, and the page cannot unset a store name that the secret detector flags (`secrets unset <name> --env <env>` in a terminal). In the setup guide, the CLI reference, and `request_value`.
- **Diagnose:** the identity rows of the `doctor` table, the `Projects (projects.toml)` section, the states `missing`, `linked`, and `duplicate` of `project list`, and step 6 (stop on an identity problem). `run_app` has the identity errors in its exit table.
