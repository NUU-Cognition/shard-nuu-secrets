Install it with the exact version: `npm install -g @nuucognition/secrets-cli@0.4.0-beta.0`. `0.3.0-beta.0` and older have no `secrets pull`.

- **Task 022: `secrets pull` in place of the `run` command.** The agent runs `secrets pull --check`, then `secrets pull` when the block of `.env.local` is not current, then the normal command of the program (`pnpm dev`, `next dev`, `vite`, `npx convex dev`). No file of the shard names the removed command or its alias as a command to use. An old instruction that uses it gives `Unknown command: run`: the agent pulls, then runs the normal command.
- **Rule 15: `secrets pull` and the block of `.env.local`.** The agent never reads, prints, copies, or changes the values in the block, and never opens or searches `.env.local`. It changes a value in the store (the operator, with `secrets set` or `secrets ui`), never in `.env.local`. When `secrets pull` stops on a managed name outside the block (`PULL_MANAGED_OUTSIDE`), the agent reports each line number and name to the operator, and does not delete the line without the approval of the operator. `secrets pull --force` needs the approval of the operator (on the list of Rule 5). `--env prod` and `--env deploy` are refused (`PULL_ENV`): no other way puts a production value into a file. A `.env.local` that Git does not ignore: `secrets project gitignore`; a tracked `.env.local`: the operator decides about `git rm --cached`. No `secrets pull` in the scripts of `package.json` (CI has no key). In a headless session, a managed name outside the block, a changed block, a broken block, a tracked `.env.local`, and a link are blockers. The rule is in the rules, the init (item 15), and the headless init (item 12).
- **Rules 1, 2, 3, 6, 7, 11, 13, and 14:** the safe signals of a variable are the `pull` line, `secrets pull --check`, and `secrets doctor` (no more check in a child shell); `secrets pull` is the one writer of a file with values, and the Convex lines of `.env.local` stay out of the target `local`; never load `.env.local` into a shell; `secrets pull`, `pull --check`, and `pull --all` on the agent list; the agent continues with `secrets pull`; the expiry warnings and the vault rule name `pull`.
- **`run_app`** is new: the check, the pull, the `pull` line and its warnings, the normal command (with `node --env-file=.env.local` for a program that does not read the file), each refusal of the pull with its action, the exit table, `--all`, and no `secrets pull` in project files.
- **The CLI reference:** the section `secrets pull` (the options, the block, the write, the output, the `--check` output, the refusal codes `PULL_MANAGED_OUTSIDE`, `PULL_CHANGED_BLOCK`, `PULL_BROKEN_BLOCK`, `PULL_NOT_IGNORED`, `PULL_TRACKED`, `PULL_LINK`, `PULL_FILE`, `PULL_FOLDER`, `PULL_FOLDER_CHANGED`, `PULL_FILE_CHANGED`, `BAD_VALUE`, `PULL_ENV`, `PULL_NO_REPOSITORY`, `NO_PROJECTS`, `PULL_REFUSED`); the install of `0.4.0-beta.0` (one command, `secrets`); the `.env*` lines of `doctor`; `setup --print` ends with `secrets pull`; the new messages; the exit statuses with no program run; the known limit 3 (the plaintext file on the disk) in place of the Turborepo limit.

- **Task 030: store projects, `shared`, declared environments, and tags** (the CLI v2 work of Tasks 025 to 027, read at `c2623dc` of `even-macbook`). All of the v2 work ships in npm `0.4.0-beta.0` (Task 024).
  - **The model:** a secret name is `<project>/<VARIABLE>`; the project `shared` holds the one copy of a value that many projects use; an entry with no `ref` is an implicit ref to its own project; a link is `secret://shared/<NAME>`, and a ref can point only to `shared` or to the own project; each secret declares its environments (default `dev`, `preview`, `prod`; a platform credential `deploy`), and a value in an undeclared environment is not delivered; each environment reads only its own store file, so `preview` needs its own values; tags (`#convex/deploy-keys`, with children and records in `tags.toml`) in place of the groups by provider; the platform credentials `shared/VERCEL_TOKEN`, `shared/VERCEL_TEAM_ID`, `shared/RAILWAY_TOKEN`, and `<project>/CONVEX_DEPLOY_KEY_DEV|_PREVIEW|_PROD`.

A value that another project has: the operator decides and runs the move to `shared`. In a headless session, these cases are blockers. Rule 5 lists `env <name> <envs>`, `tag add|rm|edit|rename`, `vault tag add|rm`, and the migration; Rule 6 lists `secrets list`, `secrets env <name>`, and `secrets tag list`. - **Task 035: the migration guide for a store of the previous version.**
  - **Breaking changes of the CLI `0.4.0-beta.0`** (for each team with a store of `0.3.0-beta.0` or earlier):

  - **The guide** [[dev-knw-nsec-migrate_v2]] (`knowledge/dev-knw-nsec-migrate_v2.md`): who must migrate, what changes, the order of the steps (the backup with a Git tag and a clone, the CLI update on each machine first, `secrets store migrate --plan`, the plan edit, `--apply <plan>`, the preview values, `secrets refs fix --all`, `secrets project add`, the old `secret` prefix, the old `.env*` lines, `secrets pull --all`, and `doctor` with 0 fail), each other machine, CI, the rollback (the tag, `git revert`, the old CLI, and the restore of the local files `projects.toml` and `secrets.local.toml` from the backup of step 1), and the test of the guide on a test store of format 1. ## 0.8.0

For the CLI npm `@nuucognition/secrets-cli@0.3.0-beta.0`: the code of the machine branch `even-macbook` of `NUU-Cognition/secrets` at `99cb649`, which goes to canon for this version. It adds the vault (Notepad 006, Tasks 010 to 013) to the CLI of `0.2.0-beta.1`. Install it with the exact version: `npm install -g @nuucognition/secrets-cli@0.3.0-beta.0`. `0.2.0-beta.1` and older have no vault.

- **Rule 14: the vault is for the operator.** Agents never read or write a vault text: never `secrets vault show` (also `--copy`), `vault edit`, or `vault set`, also when the operator asks, and never a read of the clipboard. When a task needs a password, a login, or another text from the vault, the agent asks the operator to do that step. `secrets vault list` is an agent command (names only). `vault mv|rm` need the approval of the operator. The vault is not part of the environments: an agent never tells the operator to put a value of an environment into the vault, or a vault text into `secrets.toml`. In a headless session, a task that needs a vault text is a blocker. The rule is in the rules, the init (item 14), and the headless init (item 11). Rule 13 stays the rule for moved refs, collections, and expiry dates.
- **Rules 4, 5, 6, 7, 10, and 11:** no access to a vault file; `vault mv|rm` on the operator list, and `vault show|edit|set` never for an agent; `vault list` on the agent list; a vault text is not a value of an environment; `UNSAFE_VAULT`; the page shows the vault, and a reveal of a vault entry writes `ui-reveal.log` too.
- **Request a value:** the new step 5 (a step that needs a vault text: the entry name from `vault list`, the step for the operator, never the text). The steps 5 to 8 of 0.7.1 are now 6 to 9.
- **Diagnose:** the `vault:` lines of `doctor`, the vault line of `store sync`, and `UNSAFE_VAULT`.
- **Set up a project:** a password or a login that no program reads gets no entry: it belongs in the vault.
- **The model:** the vault files, the vault ops of the change log, the metadata check of a vault file (`UNSAFE_VAULT`), and the section The vault.
- **The CLI reference:** the install of `0.3.0-beta.0`; `secrets vault list`; the operator rows of `vault show|edit|set|mv|rm` (the terminal rules, the `\xNN` and `\u{XXXX}` screen form, the clear of the clipboard after 30 s with `cleared in 30 s` or `not cleared`, the exact bytes of `vault set`, `Your new text was not saved.`); the vault error codes and the two `NO_ACCESS` messages; `UNSAFE_VAULT` (paths, and the metadata refusal of a vault file); the vault lines of `doctor`, `store sync`, and `log --name`; and the known limits 31 and 32.
- **The setup guide:** the section The vault (the operator commands, the groups, the exact bytes, the screen, the clipboard, edit, and the `--rotate` line), and the Vault view of the page (Show, Copy, Edit, the typed name for Remove, and the lock).
- **The description** names the vault (passwords and logins) again.

## 0.7.0

For the CLI of npm `@nuucognition/secrets-cli@0.2.0-beta.0`, built from the draft commit `9b7ad5c` of `NUU-Cognition/secrets` (not on canon, which is `633496d`). Install it with the exact version: `npm install -g @nuucognition/secrets-cli@0.2.0-beta.0` (the npm tags `beta` and `latest` still give `0.1.0-beta.1`). It adds the change log, `secrets mv`, the ref check, the collections, and the expiry dates (Notepad 005) to the CLI of canon `633496d`. Canon `633496d` and npm `0.1.0-beta.1` do not have these parts.

- **Rule 13: moved refs, collections, and expiry dates.** Agents can run `secrets log`, `secrets refs`, `secrets refs fix --dry-run`, `secrets collection list`, and `secrets expiry list`. Agents run `secrets mv`, `collection create|edit|rename|rm`, `expiry set|clear`, and `refs fix` only with the approval of the operator (Rule 5). The approval names the exact command: a general task such as "fix the refs" is not an approval. With no terminal, `refs fix` needs `--yes`: the agent adds it only after the operator approved the plan of `--dry-run`, and runs `--dry-run` again first. A missing ref with a `moved` hint leads to `secrets refs fix --dry-run` and a question to the operator; a `removed` ref is a question to the operator. An expiry warning (`due` or `expired`) goes to the operator; the agent never sets or clears a date. In a headless session, a moved or removed ref is a blocker, and an expiry warning goes into the result. The rule is in the rules, the init (item 13), and the headless init (item 10).
- **Rules 2, 4, 5, 6, 7, 10, and 11:** the `run` command writes no `.env` file (a file with values comes only from a redirect of `secrets export`), and the Convex names of `.env.local` (`CONVEX_DEPLOYMENT`, `NEXT_PUBLIC_CONVEX_URL`) stay out of `secrets.toml`; no hand edit of `collections.toml`, `metadata.toml`, or `changes.jsonl`; the new operator and agent commands; a moved ref is not a missing value; the page shows the collections and the change log.
- **Diagnose:** the new step 7 (moved and removed refs: `secrets refs`, `refs fix --dry-run`, the request for approval, `--yes` only after the approval), the `doctor` lines of moved refs and expiry dates, and the new lines of `store sync`. The steps 7 to 10 of 0.6.0 are now 8 to 11.
- **Request a value, run an app, and plan a push:** a moved or removed ref is not a missing value; the optional warning; the expiry warnings; `plan` stops on a moved `optional` ref. The page way of `request_value` names the store choice.
- **Set up a project:** use an existing collection for a new secret name (`secrets collection list`), make no collection record, and give the Convex names no entry.
- **The model:** the new store files (`collections.toml`, `metadata.toml`, `changes.jsonl`), and the sections Collections, Expiry dates, and The change log and moved refs (the trace and the states of `secrets refs`).
- **The CLI reference:** the install of `0.2.0-beta.0`, `secrets log`, `secrets refs`, `refs fix --dry-run`, `collection list`, `expiry list`, the operator commands `mv`, `collection create|edit|rename|rm`, `expiry set|clear`, `set --expires`, and `refs fix`, the hints and warnings of the `run` command, `export`, `plan`, and `doctor`, the new `store sync` lines, the new messages, and the known limits 28 to 30.
- **The setup guide:** the section "Collections, expiry dates, and the change log" (operator commands), and the page of `0.2.0-beta.0`: the login link unlocks with the one identity, the store choice, and the side bar of the store (projects, collections, Activity, Health).

## 0.6.0

For the CLI of Mission 002 (canon `633496d`): the CLI of canon `471e270` with the identities, the project index, and the local web page `secrets ui`. The npm version `0.1.0-beta.1` does not have these parts.

- **Rule 11: `secrets ui` is for the operator.** Agents never run `secrets ui` (also when the operator asks, and with no way around the terminal check), never open its URL, login link, page, or API, and never read values from it. A login link is a credential. The rule is in the rules, the init, and the headless init.
- **Rule 12: identities.** The agent uses the identity that the CLI selects. It does not add `--identity` or set `SECRETS_IDENTITY` or `SOPS_AGE_KEY_FILE` unless the operator names the identity. `identity add|use|rm`, `project identity <name>`, `project identity --clear`, and `project forget` are operator commands. `identity list`, `project list`, and `project identity` (show) are agent commands. On `LINKED_MAPPING`, `MAPPING_CHANGED`, `OUTSIDE_PROJECT`, `DUPLICATE_PROJECT`, `UNKNOWN_IDENTITY`, `PROJECT_INDEX`, the parent-identity warning, or the link warning, the agent stops and gives the operator the exact message and the remedy of the CLI. In a headless session, these are blockers.
- **The model:** the selection order of the key (`--identity`, `SECRETS_IDENTITY`, `SOPS_AGE_KEY_FILE`, the project identity, the default, the default key file), where the project identity applies, and the project index.
- **Request a value:** the operator sets a value with `secrets set` or in the page of `secrets ui`; then the agent continues with the `run` command. The key request covers the key file of an identity.
- **The setup guide:** the sections Identities (make the identity with the least access the default), The project index (`project list|forget`), and The UI: `secrets ui` (the start, the login link, the identity choice, the lock, the hidden values, the writes, Quit).
- **The CLI reference:** `--identity` on each command that decrypts or reads the key, `identity list`, `project list`, `project identity`, the operator commands `identity add|use|rm`, `project identity <name>`, `project forget`, and `secrets ui`, the `doctor` lines of the key selection and the project index, the identity messages, and the new known limits (items 23 to 27).
- **`secrets project add <path>`** (an agent command): it finds each `secrets.toml` under a folder (or takes one `secrets.toml`) and adds its project to the project index. It writes only `projects.toml` and reads no store and no value. In Rule 6, the CLI reference (the search, the limits, the line words `added`, `updated`, `known`, `skipped <reason>`, `--dry-run`, `--json`, and the codes `NO_FOLDER`, `LINKED_FOLDER`, `BAD_FOLDER`), the setup guide (the project index, and "Add projects from a folder" of the page when the side bar has no projects), the model, and `diagnose` (step 6: a missing project, first with `--dry-run`).
- **The page writes in part:** `Only a part of the change was saved.` (`PARTIAL_WRITE`) with "Undo the saved part" for 60 seconds, and the page cannot unset a store name that the secret detector flags (`secrets unset <name> --env <env>` in a terminal). In the setup guide, the CLI reference, and `request_value`.
- **Diagnose:** the identity rows of the `doctor` table, the `Projects (projects.toml)` section, the states `missing`, `linked`, and `duplicate` of `project list`, and step 6 (stop on an identity problem). `run_app` has the identity errors in its exit table.
